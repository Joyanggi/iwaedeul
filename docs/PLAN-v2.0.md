## 1. 왜 네이티브인가 — 웹앱 제약으로 못 했던 것

README "Limitations"와 DEV-RECORD의 "이 환경에서 확인된 제약"에 쌓인 것들이다. **새 기능 요구가 아니라,
플랫폼이 막아서 접었던 것**이 전환으로 열린다. 이 표가 전환의 값이고, 단계 PLAN의 입력이다.

|---|---|---|---|---|
| ① | **화면이 꺼지면 휴식 종료 알림이 없다.** 서버 없는 PWA에서 경로가 전부 막혀 "구현하지 않기로 확정"했다 | README Limitations, v1.1 T6 | `expo-notifications`의 **로컬 알림 예약**. 서버가 필요 없다 — 타이머를 걸 때 종료 시각으로 예약하고, 일찍 끝내면 취소한다 | v2.2 |

백그라운드에서 긴 연산을 돌리는 것, 애플 심사 없이 남에게 배포하기(무료 계정은 내 기기만, 7일 만료). HealthKit·워치·위젯은
가능하지만 **이번 범위가 아니다**(12절).

## 3. 코드 재사용 지도 (실측)

`src/lib`의 57개 파일 중 **브라우저 API를 쓰는 것은 11개뿐이다**(`document`·`window`·`navigator`·
`localStorage`·`indexedDB`·`AudioContext`·`URL.createObjectURL` 검색). 나머지 46개와 테스트 64개는
**순수 TypeScript라 그대로 간다.**

| 구분 | 지금 | 전환 |
|---|---|---|
| 판정·계산 (순수 46개) | `suggestNextDay`, `progression`, `dashboard`, `phaseReadiness`, `weightScale`, `diet*`, `dayChoice`… | **그대로.** `src/core/`로 옮기고 import 경로만 바꾼다 |
| 타입·시드 | `src/types.ts`, `src/data/` | 그대로 |
| 상태 | `src/store/` (zustand) | 그대로 |
| 플랫폼 의존 11개 | `backup` `beep` `chartTheme` `commitEdits` `gist` `gistSync` `pickFile` `platform` `secrets` `share` `useRestTimer` | **어댑터로 교체**: 파일 저장→`expo-file-system`, 공유→`expo-sharing`, 소리→`expo-audio`, 비밀값→`expo-secure-store`, 타이머→같은 "종료 시각 저장" 규칙 + 알림 예약 |
| 화면 | `src/screens` 11개, `src/components` 35개, `src/ax` | **다시 짓는다.** 화면의 판정은 이미 `lib`에 있으므로 옮기는 것은 배치와 부품이다 |
| DB 접근 | `src/db` (Dexie) | **다시 짓는다**(4절) |

> 재사용의 전제: 코어는 **DB와 화면을 모르게** 유지한다. 지금도 대체로 그렇다 — 이 경계를 깨는 import가
> 생기면 전환 비용이 다시 올라가므로, v2.1에서 `src/core`는 `react`·`dexie`·`expo-*`를 import하지 못하게
> 검사로 막는다(지금 `scripts/quality-scan.mjs`와 같은 자리).

## 4. 데이터 — DB 재설계

### 4.1 무엇을 바꾸고 무엇을 안 바꾸나

**스키마의 모양은 지금 일곱 테이블을 그대로 옮긴다**(`routines` `exercises` `sessions` `settings`
`exerciseNotes` `dietPlans` `dietDays`). 세션 안의 중첩(`entries[].sets[]`)은 **JSON 열로 둔다.**

- 왜 정규화하지 않나: 지금 판정 함수들이 **세션 객체 하나를 통째로 받는다**(`doneSetsAll(entry)`,
  `progressionSuggestions(last, …)`). 정규화하면 코어 46개를 전부 고쳐야 하고, 그 순간 "그대로 간다"는
  전환의 전제가 깨진다. 기록은 한 세션이 한 번에 쓰이고 한 번에 읽히는 **묶음(aggregate)**이라 JSON이 맞다.
- 대신 **쿼리에 쓰는 값만 열로 승격한다**: `sessions(id PK, date, day_id, routine_id, mode, started_at,
  ended_at, body_json)` + `index(date)`, `index(day_id, date)`. 이것이 제약 ⑥(전체 조회)의 처방이다.
- 정규화는 **분석이 실제로 느려질 때** 별도 PLAN으로 한다. 그때는 파생 테이블(읽기 전용 집계)을 두는 쪽이
  먼저다 — 원천을 쪼개는 것보다 되돌리기 쉽다.

### 4.2 마이그레이션 (지금 쓰는 사람의 기록을 잃지 않는다)

1. 웹앱 설정 → **내보내기(JSON)**. 지금 그대로다(`SCHEMA_VERSION` 유지).
2. 네이티브 첫 실행 → **가져오기**. 파일 선택(`expo-document-picker`)으로 같은 JSON을 읽어 SQLite에 넣는다.
3. 두 앱을 한동안 같이 쓴다. **전환 기간에는 웹이 원천이고 네이티브가 사본**이다 — 반대로 하면 양쪽에서
   따로 기록해 합칠 수 없는 날이 생긴다. 네이티브로 넘어가는 날짜를 사람이 정하고, 그날 한 번 더 가져온다.
4. 동기화(v2.4)가 붙으면 그때부터 기기 사이는 서버가 맞춘다.

> 검증: 가져오기 전/후로 **세션 수·세트 수·총 볼륨·식단 일수가 같은지** 코어 함수로 재서 보여준다.
> "들어갔다"가 아니라 "같다"를 보여야 한다.

### 4.3 동기화는 v1.22를 그대로 따른다

PLAN v1.22(머지됨, 미구현)가 정한 것 — Supabase, 행 단위, 내용 지문(SHA-256) 비교, 마지막 업로드 우선,
이메일+비밀번호, 장부는 별도 저장소 — 을 **다시 설계하지 않고 저장 계층만 SQLite로 바꿔** v2.4에서 구현한다.
장부는 별도 DB 파일 대신 **같은 DB의 `sync_ledger` 테이블**로 둔다(네이티브에서는 "다른 DB"의 이유였던
되돌리기 제약이 없다 — 앱 버전이 내려가면 스토어가 막는다).

## 5. 디자인 — Astryx를 토대로, 질감은 iOS

**토대는 Astryx다.** 색·간격·반경·타이포 스케일·움직임 시간은 지금 테마에서 값을 뽑아
`theme.ts`(라이트·다크 두 벌)로 옮긴다. 바꾸는 것은 **부품의 구현과 관용구**다 —
웹 부품을 RN으로 흉내 내면 "웹앱을 앱처럼 보이게 한 것"이 되고, 그게 지금과 같은 자리다.

| 지금 (웹) | 네이티브에서 | 왜 |
|---|---|---|

## 7. 다크모드 시인성 — 진단과 처방 (실측)

**재현**: 다크에서 버튼의 면과 테두리가 바탕에 녹는다. 라이트에서는 보인다.

**원인은 셋이고, 전부 토큰 값이다.** `@astryxdesign/theme-neutral@0.7.13`의 값을 꺼내
대비(WCAG 2.2 상대 휘도비)를 쟀다.

| 측정 | 라이트 | 다크 | 판정 |
|---|---|---|---|
| **카드 바탕 vs 본문 바탕** (`--color-background-card` vs `--color-background-body`) | `#ffffff` vs `#f1f1f1` = **1.13:1** | `#1b1b1b` vs `#1b1b1b` = **1.00:1** | 다크에서 **카드와 바탕이 같은 색이다.** 면 위계가 아예 없다 |
| **secondary 버튼 면** (`--color-neutral`, 앱에서 101곳으로 가장 많이 쓴다) | `#0000000F` → `#f0f0f0`, 카드 위 1.14:1 | `#ffffff1A` → `#323232`, 바탕 위 1.34:1 | 둘 다 낮지만 라이트는 **흰 카드 + 그림자**가 구조를 대신 말해 준다 |
| **테두리** (`--color-border`) | `#00000014` → `#ebebeb`, 1.19:1 | `#ffffff1A` → `#323232`, 1.34:1 | 다크에서는 **테두리 값과 버튼 면 값이 같다**(둘 다 흰색 10%). 테두리를 둘러도 경계가 안 생긴다 |
| 그림자 | 보인다 | 거의 안 보인다 | 그림자는 빛을 가정한다. 다크에서 깊이는 **면 밝기**로 말해야 한다(iOS도 같다) |

즉 **다크에서만 구조를 말하는 수단이 전부 꺼져 있다** — 카드가 바탕과 같고, 그림자가 없고,
테두리와 면이 같은 값이다. 라이트가 멀쩡한 것은 흰 카드 하나가 셋을 대신하고 있어서다.

**처방** — `src/ax/theme.ts`에서 토큰 세 개의 **다크 값만** 올린다(라이트는 그대로 둔다).
값은 팔레트 단계로 고른다(테마 파일의 규칙).

| 토큰 | 다크 지금 | 다크 제안 | 결과 |
|---|---|---|---|
| `--color-background-card` | `#1b1b1b` (바탕과 같음) | `neutral.dark[15]` `#262626` | 카드가 바탕에서 **1.14:1**로 떠오른다 (= Astryx가 이미 `--color-background-surface`에 쓰는 값) |
| `--color-neutral` (secondary 면) | 흰색 10% → `#323232` | `neutral.dark[30]` `#474747` | 카드 위 **1.63:1**, 바탕 위 1.85:1. iOS 다크의 보조 버튼 면(systemGray4~5)이 같은 대역이다 |
| `--color-border` | 흰색 10% → `#323232` | `neutral.dark[35]` `#525252` | 바탕 위 **2.20:1**. 구분선으로 과하지 않으면서 면과 다른 값이 된다 |

**검증**(단계 PLAN이 테스트로 고정한다):
1. 토큰 단위 테스트 — 다크에서 ① 카드 vs 바탕 ≥ 1.1:1 ② 버튼 면 vs 카드 ≥ 1.5:1 ③ 테두리 vs 카드 ≥ 1.5:1,
   그리고 **테두리 값 ≠ 버튼 면 값**. 숫자를 코드로 재니 눈으로 보는 판정이 아니다.
2. 화면 검증자가 **다크 스크린샷**을 라이트와 같은 장면으로 찍어 나란히 본다(지금 `docs/screenshots/`에 다크가 없다).
3. 실기기: 밝기를 낮추고 헬스장 조명(역광)에서 본다. 이건 사람만 할 수 있다.

> 웹앱은 고치지 않는다(10절 개정). **네이티브 테마를 처음 만들 때(v2.1) 이 값으로 시작한다** —
> 라이트에서 베껴 온 뒤 다크를 나중에 손보는 순서가 지금의 결함을 만들었다. 두 벌을 같이 만든다.
> 전환 기간(v2.2까지)에는 웹앱의 다크가 그대로 불편하다. 그 값을 치르고 한 번만 고치기로 했다.

## 8. 폰트

지금 앱은 글꼴을 지정하지 않는다(Astryx 테마의 기본값을 쓰고, 앱 CSS에는 모노스페이스 한 줄뿐이다).

- **본문·제목: 시스템 글꼴**(iOS `SF Pro`, 한글은 `Apple SD Gothic Neo` / 안드로이드 `Roboto`+`Noto Sans KR`)
  **+ Dynamic Type**. 이유: ① 폰 설정의 글자 크기를 따라가는 것이 네이티브 질감의 절반이다
  ② 번들 크기 0 ③ 한글·숫자·영문이 섞인 줄에서 베이스라인이 안 깨진다.
- **숫자는 tabular(고정폭)**. 무게·반복수·타이머가 1자리씩 바뀔 때 줄이 흔들리지 않는다.
  SF는 `fontVariant: ['tabular-nums']`로 켠다.
- **대안: Pretendard Variable** — 한글 리듬이 더 트렌드에 맞다는 평이고 앱에서 많이 쓴다.
  대신 번들에 1.5~2MB가 붙고 Dynamic Type과 손발을 맞춰야 한다. **사람이 정할 것**(13절).
- 제목·본문·캡션의 크기·굵기 단계는 Astryx 타이포 스케일을 그대로 쓰되, iOS Text Style
  (largeTitle/title/body/footnote)에 1:1로 매핑해 Dynamic Type이 그대로 먹게 한다.

## 11. 검증 — 실기기가 기준이다 (시뮬레이터 없음)

**전제가 하나 바뀌었다**: 작업용 맥북이 iOS 시뮬레이터를 제대로 못 돌린다. 그래서 "시뮬레이터에서 돌려 본다"가
이 프로젝트에는 없다. 대신 **USB로 연결한 실제 아이폰**이 유일한 실행 환경이고, Claude는 **mobile MCP**로
그 기기를 본다(화면 읽기·탭·입력·스크린샷).

Claude Code 팀이 쓰는 기준과 같은 자리다 — *"Running the app end to end matters more than tests.
You wouldn't ship an iOS change without trying it in a simulator... Ask it to use ... an iOS or Android MCP
for mobile."* 우리는 그 자리를 시뮬레이터 대신 **진짜 기기**로 채운다(오히려 더 믿을 만하다).

### 11.1 층 (싼 것부터)

| 층 | 무엇 | 어디서 | 누가 |
|---|---|---|---|
| ① 코어 | 단위 + **속성 테스트**(fast-check, 이미 쓰고 있다) | 어디서나(노트북 부담 없음) · CI | 구현자 |
| ② 차이 | **차등 테스트** — 같은 입력을 **웹 코어와 네이티브 코어**에 넣고 결과를 비교 | CI | 구현자 |
| ③ 조립 | 타입·린트·JS 번들 | CI(클라우드 세션 포함) | CI |
| ④ **실기기** | 유선 아이폰에서 **스모크 시나리오** + 스크린샷 | 맥북 + 폰 | 화면 검증자(mobile MCP) |
| ⑤ 사람 | 소리·햅틱·역광 가독성·"쓸 만한가" | 헬스장 | 사람 |

②가 이 전환의 핵심 안전장치다. 판정 로직을 그대로 옮기는 전환이므로 **옛 시스템이 정답지**가 된다 —
세션 기록 샘플을 넣고 `suggestNextDay`·`progressionSuggestions`·볼륨·e1RM의 출력이 웹과 **한 글자도 다르지 않은지**
비교한다. 다르면 전환이 뭔가를 바꾼 것이다. (차등 테스트는 마이그레이션에 가장 잘 듣는 도구다.)

### 11.2 실기기 연결 (한 번 해 두는 것)

`.claude/skills/verify-device/SKILL.md`에 절차가 있고, MCP 서버는 레포의 `.mcp.json`에 등록해 뒀다
(`@mobilenext/mobile-mcp`). 사람이 맥북에서 한 번 해 둘 것:

1. 아이폰 USB 연결 → 맥 **신뢰** → 아이폰 **개발자 모드** 켜기
2. `xcrun devicectl list devices`로 기기가 `connected`인지 확인 — **여기서 안 보이면 MCP 문제가 아니다**
3. mobile MCP의 DeviceKit 에이전트를 Personal Team으로 서명해 설치(번들 ID는 고유값으로, 7일마다 재서명)
4. 터널·포트 포워딩은 mobile MCP(mobilecli)가 직접 연다. go-ios·WebDriverAgent는 쓰지 않는다

> 2026-11-26 정정: 처음엔 go-ios 터널 + WebDriverAgent로 적었으나, 실제로 붙여 보니 mobilecli가 터널·포워딩·에이전트를
> 모두 스스로 관리했고 go-ios 터널은 같은 포트를 두고 충돌했다. 정본 절차는 스킬 0절.

### 11.2-A 빌드는 로컬 Xcode다 (무료 Apple 계정이라 클라우드 빌드를 못 쓴다)

사람 확인(2026-11-26): **Apple Developer Program(연 $99)에 가입돼 있지 않다.** 아이폰은 개발자 모드이고
Xcode에 개인 Apple Development 인증서가 등록돼 있다(무료 Personal Team). 여기서 따라오는 제약:

| 무료 계정에서 | 값 | 설계에 미치는 영향 |
|---|---|---|
| 프로비저닝 프로파일 만료 | **7일** | 주 1회 `npx expo run:ios --device`로 다시 설치해야 한다. mobile MCP의 DeviceKit 에이전트도 같은 날 재서명한다. 달력에 고정 작업으로 둔다 |
| 기기당 설치 앱 | 3개 | 개발 빌드 + DeviceKit 에이전트 = 2개. 프리뷰 빌드를 따로 깔지 않는다 |
| 등록 기기 | 3대 | 아이폰 하나면 충분 |
| **EAS 클라우드 빌드(기기용)** | **못 쓴다** — Apple이 개발용 프로비저닝을 API로 내주지 않는다 | **빌드는 맥북의 Xcode에서** 돈다. 앞서 적었던 "클라우드에서 굽는다"는 틀렸다 |
| 원격 푸시·IAP·Sign in with Apple·iCloud·App Groups·연관 도메인 | 쓸 수 없다 | 이번 범위에 없다. **로컬 알림은 푸시 엔타이틀먼트가 아니므로 쓸 수 있다** — v2.2의 첫 실기기 확인 항목으로 못 박는다(된다고 가정하지 않는다) |
| TestFlight·배포 | 못 쓴다 | v2.5의 "출시"는 유료 가입 뒤로 미룬다. 그전까지 배포처는 **내 아이폰 한 대**다 |

**약한 맥북에서 로컬 빌드를 견디는 법** — 네이티브 빌드는 자주 하지 않는다.
개발 클라이언트(dev client)를 한 번 구워 두면 **JS 변경은 다시 굽지 않고 Metro가 넘긴다.**
네이티브 빌드가 필요한 때는 ① expo 모듈을 추가·제거했을 때 ② 권한·아이콘·스플래시 같은 네이티브 설정이
바뀌었을 때 ③ 7일 만료로 다시 서명할 때, 이 셋뿐이다. 그 외 하루의 작업은 전부 Metro 위에서 돈다.

**무거운 검사는 클라우드 세션으로 넘긴다.** 전체 테스트·빌드·차등 테스트처럼 CPU를 먹는 것은
Claude Code 클라우드 세션(Pro에 포함, 같은 한도를 쓴다)에서 돌리고, 맥북은 **기기 설치와 구동**만 맡는다.
단 병렬 세션은 한도를 그만큼 빨리 쓰므로 **동시 두 개까지**로 둔다.

> 유료 가입은 **v2.5(출시) 직전**이면 된다. 다만 7일마다 다시 설치하는 마찰이 거슬리면 그때 앞당긴다 —
> 유료로 바꾸면 프로파일이 1년으로 늘고 TestFlight가 열린다.

### 11.3 스모크 시나리오와 채점표

`docs/FEATURE-MAP.md`(v2.1에서 만든다)가 **사용자 관점의 흐름 목록**이고, 그것이 곧 채점표다.
최소 스모크 넷: 헬스장 경로(세션 시작→세트 체크→휴식→**화면 끄고 알림**→마감) · 재시작 후 기록 보존 ·
테마 3지(라이트·다크·시스템 스크린샷) · 키보드와 입력.

기계가 못 보는 것(알림 소리, 햅틱 세기, 역광 가독성)은 **"사람이 볼 것"으로 PR에 넘긴다.**
Claude가 그것을 "확인했다"고 적는 것을 금지한다.

### 11.4 검사 장치 이관

| 장치 | 지금(웹) | 전환 후 |
|---|---|---|
| `npm run check` | 흔적·Astryx 뒷걸음·린트·knip·테스트·빌드 | **Astryx 뒷걸음 검사는 역할이 끝난다**(웹 CSS가 없어진다) → **코어 경계 검사**(`src/core`가 RN·DB·expo를 import하지 않는가)로 바꾼다 |

| 속성 테스트 | `src/lib/properties.test.ts` | 그대로 + **차등 테스트** 추가(11.1 ②) |

### 11.5 커밋에 검증 도장 (observe → enforce)

새 관문은 **observe 모드로 먼저 켠다**(막지 않고 기록만). Claude Code 팀이 쓰는 방식이다.

1. 커밋 메시지에 `검증: check | device | none` 한 줄을 남긴다. **`none`도 적는다** — 안 적으면 셀 수 없다.
2. `scripts/agent-guard.mjs`(이미 있는 PreToolUse 훅)에 모드를 더한다: `off` → `observe`(로그만) → `enforce`(차단).
3. 한 세션에서 **두 번 막혔으면 세 번째는 통과**시킨다. 완벽하지 않은 장치에 작업이 갇히지 않게.

### 11.6 어느 기계에서 도는가 (2026-11-26)

**전부 맥북 한 대에서 돈다.** Orca 하네스를 Windows에서 맥북으로 옮겼다(`CLAUDE.md` 환경).
빌드·기기 설치·mobile MCP가 전부 맥에서만 되므로, 코드와 검증을 다른 기계에 두면 왕복이 생긴다.

대신 사양이 넉넉하지 않으므로 **동시에 도는 것을 줄이는 것이 규칙**이다.

| 무엇 | 어디서 | 규칙 |
|---|---|---|
| 지휘자·설계자·검토자·구현자·리뷰어 | 맥북 Orca | **동시 일꾼 하나.** 지금도 그렇지만 이제는 성능 때문이기도 하다 |
| `npm run check`·전체 테스트 | 맥북, 또는 **클라우드 세션** | Metro·Xcode가 떠 있으면 클라우드로 보낸다(Pro에 포함, 같은 한도) |
| 네이티브 빌드(`expo run:ios --device`) | 맥북만 | 자주 하지 않는다(11.2-A) |
| 실기기 검증(mobile MCP) | 맥북 + 유선 아이폰 | 폰이 꽂혀 있을 때만 도는 수동 관문 |

**하네스와 플랫폼을 같은 라운드에 바꾸지 않는다.** 하네스 변경(검토자 한 명·`REVIEW.md`·방아쇠·스킬)은
2026-11-26에 먼저 들어갔고, 전환은 그 위에서 시작한다. v2.1에서 무언가 어긋나면 원인이 둘 중 어느
쪽인지 먼저 가린다.

## 15. 디렉토리 구성 (전환 후)

경계가 곧 규칙이다. 지금 흩어져 있는 것을 **코어 / UI / 플랫폼 / 하네스** 넷으로 가른다.

```
.
├ CLAUDE.md                  # 모든 세션이 읽는 공통 규칙 (짧게 유지, 나머지는 가리키기만)
├ REVIEW.md                  # 이 레포에서 무엇이 "실패"인가 — 리뷰어가 읽는다 (main 판본)
├ AGENTS.md                  # CLAUDE.md를 자동으로 안 읽는 도구용 포인터
├ .mcp.json                  # 프로젝트 MCP 서버 — mobile(실기기)
├ .claude/
│   ├ settings.json          # PreToolUse 훅(agent-guard) · 검증 도장 모드
│   ├ commands/coord.md      # 지휘자 호출
│   └ skills/
│       ├ verify/            # 커밋 전에 돌리는 것 (검사 묶음·화면 촬영·데이터 왕복)
│       ├ verify-device/     # 유선 아이폰 + mobile MCP 스모크
│       └ release/           # (v2.5) EAS 빌드 → TestFlight 절차
├ agents/                    # 역할 규칙 (지휘자·설계자·검토자·구현자·리뷰어·화면 검증자…)
│   └ coordinator/           # 흐름별 지휘 규칙 (설계·배치·PR·품질·접수)
├ docs/
│   ├ RELIABILITY.md         # 방아쇠 달린 과거 사고 (main 판본)
│   ├ FEATURE-MAP.md         # (v2.1) 사용자 흐름 목록 = E2E 채점표
│   ├ PLAN-*.md              # 설계 (설계자만 쓴다)
│   ├ DEV-RECORD-*.md        # 구현 기록
│   └ screenshots/<버전>/    # web/ · device/ (light·dark)
└ src/
    ├ core/                  # 순수 TS — 판정·계산·타입·시드. react·expo·DB를 import하지 않는다 (CI가 막는다)
    ├ data/                  # 루틴·종목·식단 시드 JSON
    ├ db/                    # SQLite(Drizzle) 스키마·마이그레이션·쿼리. core를 쓰고, core는 이걸 모른다
    ├ sync/                  # (v2.4) Supabase 동기화 엔진·장부
    ├ platform/              # 소리·햅틱·알림·파일·공유·보안 저장 — expo API를 쓰는 유일한 곳
    ├ ui/                    # 테마 토큰 + 부품. 플랫폼 분기(iOS/Android)는 여기서만
    └ app/                   # Expo Router 화면 트리 (탭·스택). 화면은 플랫폼을 모른다
```

규칙 셋만 지키면 이 구성이 유지된다.
1. **`core`는 아무것도 모른다** — 화면·DB·expo를 import하지 않는다. 그래서 테스트가 그대로 돌고 차등 테스트가 가능하다.
2. **`platform`만 expo를 부른다** — 소리가 안 나는 문제, 알림이 안 오는 문제를 한 폴더에서 찾는다.
3. **플랫폼 분기는 `ui` 안에서만** — 화면 코드에 `Platform.select`를 흩지 않는다.

## 16. 이 설계가 참고한 바깥 사례

Claude Code 팀이 공개한 두 글에서 **이 레포 크기에 맞는 규칙만** 가져왔다(수치나 조직 구조가 아니라).
하네스 쪽 반영은 `agents/README.md` 2절 표에, 검증 쪽은 11절에 있다.

- [How the Claude Code team does code review](https://claude.dev/blog/solving-code-review-at-anthropic/) (2026-10-15)
  — PR 전에 리뷰가 끝나 있을 것, `REVIEW.md`, 지적을 Important/Nit/Pre-existing으로, 스타일 지적은 버릴 것,
  라운드 상한과 수렴, 위험 등급으로 사람을 부를 것, 봇 승인은 사람 승인을 대신하지 못함.
- [How the Claude Code team thinks about verification](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/) (2026-11-16)
  — 검증은 **돌려 보는 것**, `verify` 스킬을 `.claude/skills/`에, 모바일은 **기기 MCP**, 세 번 실패하면 사람,
  방아쇠 달린 신뢰성 체크리스트, 검토자를 쌓지 말고 하나를 튜닝할 것, 라운드는 앞 라운드 위에 쌓을 것,
  **변경이 자기를 심사하는 규칙을 고치지 못하게** 할 것, 새 관문은 observe 모드로, 흔들리는 테스트를
  건너뛰지 말 것, 규칙도 주기적으로 쳐낼 것.

가져오지 **않은** 것과 이유: 머지 큐·피처 플래그·단계 출시(혼자 쓰는 앱이라 되돌리기가 이미 싸다),
리뷰 결과 투표용 다중 에이전트(Pro 한도), 사고 기반 일일 eval(사고 표본이 몇 건뿐이다 — 대신
`docs/RELIABILITY.md`에 방아쇠로 남긴다).

**번들 ID가 무엇인가**: 사람이 보는 이름(이왜들) 말고 **기계가 쓰는 이름**이다. 거꾸로 쓴 도메인 모양

확인하지 않는다. `com.joyanggi.iwaedeul`은 GitHub 계정 이름을 가운데에 넣어 유일성을 확보한 것이다.

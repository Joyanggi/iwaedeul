# verify — "됐다" 대신 **돌린 결과**를 낸다

커밋하기 전에 이 스킬을 쓴다. 규칙 하나: **"수정했습니다"로 끝내지 않고 돌린 출력(숫자·스크린샷)을 낸다.**

## 1. 무엇을 돌릴지 고르기

| 바꾼 것 | 돌릴 것 |
|---|---|
| `src/core`(계산·판정) | 그 파일의 테스트 → `npx vitest run src/core/<파일>.test.ts`, 그 다음 `npm run check -- --fast` |
| 화면(`src/ui`, `src/screens`) | 위 + **실기기 촬영**(3절) |
| `src/db`·백업·가져오기 | 위 + **데이터 왕복**(4절) |
| 문서만 | `npm run check -- --fast`만 |

마지막에 한 번은 **`npm run check`** 전부를 돌린다. 끝부분만 본다: `npm run check 2>&1 | tail -15`.

## 2. 검사 루프

검사가 깨지면 고치고 다시 돌린다. **상한 세 번.** 세 번째도 같은 실패면 멈추고 사람에게 가져간다
(무엇이 어떻게 실패하는지, 무엇을 시도했는지 함께).

- 깨진 테스트를 **지우거나 `.skip`하거나 `sleep`을 넣어 통과시키지 않는다.** 흔들리는 테스트는
  원인을 찾고, 끝내 못 찾으면 **지우고 왜 지웠는지 적는다.**
- 검사 자체를 고쳐서 통과시키지 않는다. 검사를 고쳐야 한다면 그게 변경의 본문이고, PR에 따로 적는다.

## 3. 화면 촬영 (실기기)

웹 촬영은 웹과 함께 지웠다. 화면은 **`verify-device`(5절)로 아이폰에서** 찍는다.

- **라이트와 다크를 같은 장면으로 둘 다** 찍는다. 다크만 깨지는 결함이 이 레포에 반복해서 났다
  (`docs/RELIABILITY.md` R12).
- 넘침·잘림·겹침·가림을 **직접 본다.** 요소 트리가 정상이어도 스크린샷을 Read로 본다.

## 4. 데이터 왕복

DB·백업·가져오기를 건드렸으면 **같은지**를 수치로 보인다("들어갔다"가 아니라).
세션 수 · 세트 수 · 총 볼륨 · 식단 일수를 바꾸기 전후로 재서 나란히 적는다.

## 5. 실기기

맥북이 시뮬레이터를 못 돌리므로 **유선으로 연결한 아이폰**이 기준 기기다.
전제와 절차는 `.claude/skills/verify-device/SKILL.md`에 있다. 이 스킬은 거기로 넘긴다.

## 6. 보고 형식 (PR 본문 "검증"에 그대로 붙는다)

```
검사: npm run check — 통과 (테스트 983)
돌려 봄: <무엇을 어떻게 돌렸는지 한 줄> → <무엇을 봤는지>
스크린샷: docs/screenshots/<버전>/device/<파일들> (라이트·다크)
방아쇠: RELIABILITY R5 R12 — <각각 어떻게 확인했는지 한 줄>
못 한 것: <돌려보지 못한 것과 이유. 없으면 "없음">
```

**"못 한 것"을 비워 두지 않는다.** 확인하지 못한 것을 적는 것이 이 보고의 절반이다.
